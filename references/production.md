# 制作细则与调用示例

## 项目记录

建议在视频工程内保存以下文件，目录名称可按现有工程调整：

- `brief.md`：主题、受众、知识结论、规格、时长、风格、音乐裁切和待确认项。
- `sources.md`：事实、来源 URL、访问日期、文案对应位置。
- `storyboard.json`：场景的起止帧、文案、动作、对应事实和事件 ID。
- `beats.json`：音乐分析结果与校准的全局拍点。
- `events.json`：关键动作与音效共用的帧时间线。
- 工程的素材目录：音乐、字体、合成音效及来源/使用范围记录。

不必为了形式创建空文件。先保存实际使用的数据。

## 节拍数据示例

以下数值仅为结构示例，不能当作真实曲目的检测结果：

```json
{
  "audio": "music.wav",
  "fps": 30,
  "trimStartSeconds": 0,
  "bpmCandidates": [120, 60],
  "timingStatus": "placeholder",
  "beats": [
    {"sourceSeconds": 0.5, "frame": 15, "kind": "unconfirmed"},
    {"sourceSeconds": 1.0, "frame": 30, "kind": "unconfirmed"}
  ]
}
```

分析时可以用环境中可用的音频工具提取 onset 和 beat 候选，再人工试听重拍。保存工具版本、检测区间和校正结果。恒定 BPM 的人工网格可用 `t(n)=offset+n*60/BPM`，但需和全曲采样点比较以发现漂移。按 30 fps 舍入的理论量化误差约为半帧；检测误差另行评估。

事件记录示例：

```json
{
  "id": "connection-01",
  "sceneId": "scene-02",
  "frame": 180,
  "action": "connection-arrives",
  "sfx": "sfx/pluck-01.wav",
  "gain": 0.25
}
```

`gain` 是初始值，不是统一混音标准。动画可以提前起势，在第 180 帧完成连接，声音也在该帧触发。场景局部时间由绝对帧减去场景起始帧得到。

## 音效合成

简单音效可离线用正弦波叠加少量泛音，添加短起音、指数衰减和淡出，导出 WAV。钟音、木琴、拨弦通过不同泛音与包络区分；先做少量音色，按主题复用。避免波形突变造成爆音。合成后与音乐一起试听；需要时做整体衰减并重新测量峰值，不用堆叠限幅掩盖混音问题。

## 十秒样片验收

至少验证一个知识句、一段线条绘制、一次关键命中、一次音效，以及可读的中文排版。观看运动中的画面，并检查关键帧，不能只看静态截图。听确认的拍点与动作是否一致；检查低音量下音乐和音效的平衡。先用较快设置预览，交付样片按目标规格输出。

## 调用示例

“使用 $vibe-knowledge-video，制作一条讲蝴蝶效应的 75 秒知识动画。Remotion，1920×1080，30 帧，横屏，中文字幕，无旁白。深蓝背景、金色线条。先核验知识点，再分析我提供的音乐，做十秒样片，检查合格后逐段完成。不要把蝴蝶效应讲成任何小事都会必然导致巨大后果。”

如果没有提供音乐，先做分镜与视觉验证并标注临时节拍；需要用户提供实际可用的音频后才能完成卡点与最终混音。
